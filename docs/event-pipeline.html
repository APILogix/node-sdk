Event Pipeline

Event Processing Pipeline

Complete documentation of the 14-stage event processing pipeline that every captured event flows through.

Pipeline Overview

Stage Details

Stage 1: Coerce to SDKEvent

Every event is normalized to the SDKEvent shape with a generated eventId and timestamp:

function ensureBaseFields(raw: SDKEvent | Event): SDKEvent {
  const eventId = raw.eventId ?? generateId()
  const timestamp = raw.timestamp ?? epochMs()
  return { ...raw, eventId, timestamp } as SDKEvent
}

Stage 2: Pre-init Buffering

If SDK is not yet initialized, events are queued for later processing:

if (!client.initialized) {
  eventQueue.add(event) // Buffer pre-init
  return true
}

Stage 3: Feature Flag Gate

Check if the event type is enabled by config/plan:

function isFeatureEnabled(event, config): boolean {
  switch (event.type) {
    case 'error': return config.enableErrors
    case 'request': return config.enablePerformance
    case 'metric': return config.enableMetrics
    case 'span': return config.enableTracing
    default: return true
  }
}

Stage 4: Normalization

Fill missing required fields, truncate oversized strings:

  • Message truncation: 2048 chars max
  • String fields: 8192 chars max
  • Object depth: 5 levels max
  • Array length: 100 items max

Stage 5: Sanitization (PII Redaction)

Deep PII scrubbing of all event fields:

  • Sensitive headers (authorization, cookie, api-key)
  • PII patterns (email, SSN, credit card, phone)
  • Sensitive key names (password, token, secret)

Stage 6: Context Enrichment

Attach trace/span IDs and breadcrumbs from AsyncLocalStorage context:

function enrichFromContext(event: SDKEvent): SDKEvent {
  const ctx = getRequestContext()
  if (!ctx) return event
  return {
    ...event,
    traceId: ctx.traceId,
    spanId: ctx.spanId,
    breadcrumbs: ctx.breadcrumbs.toArray()
  }
}

Stage 7: Error Deduplication

Suppressing duplicate errors within a configurable window (default 60s):

if (event.type === 'error' && event.fingerprint) {
  if (errorDeduplicator.isDuplicate(event.fingerprint)) {
    return false // Drop duplicate
  }
}

Stage 8: Scope Application

Merge user, tags, extra, and contexts from global scope:

function applyScopeToEvent(event): Record {
  const user = scopeManager.getUser()
  const tags = scopeManager.getTags()
  const extras = scopeManager.getExtras()
  return { ...event, user, tags, extra: extras }
}

Stage 9-10: Plugin & Event Processors

Run registered processors that can modify or drop events:

for (const plugin of client.plugins) {
  const result = plugin.processEvent(event)
  if (result === null) return false // Dropped
  event = result
}

Stage 11-12: beforeSend Hook

User-provided callback to modify or drop events (Pro+ plans):

if (client.options?.beforeSend && config.planFeatures.allowBeforeSend) {
  const result = client.options.beforeSend(event)
  if (result === null) return false
  event = result
}

Stage 13: Sampling

Trace-consistent deterministic sampling:

function shouldSample(rate: number, traceId?: string): boolean {
  if (rate >= 1) return true
  if (traceId) {
    const hash = deterministicHash(traceId) // FNV-1a
    return hash < rate
  }
  return Math.random() < rate
}

Stage 14: Queue & Persist

Add to queue and persist to disk for crash recovery:

eventQueue.add(event)
persistentStorage.persist(event) // NDJSON on disk
Important: The pipeline is designed to be defensive - any stage can fail without crashing the host. Errors are logged and the event is either processed or dropped gracefully.
