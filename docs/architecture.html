High-Level Architecture

Event Pipeline event-pipeline.ts, normalizer.ts, sanitizer.ts, deduplicator.ts 14-stage processing: normalize, sanitize, enrich, deduplicate, sample, queue

Telemetry Flow

The SDK follows a consistent flow from user code to backend:

  1. Capture: User calls captureError(), captureRequest(), etc.
  2. Validation: Event is coerced to SDKEvent shape with ID and timestamp
  3. Pre-init Buffering: If SDK not ready, events are queued for later processing
  4. Feature Gating: Check if feature is enabled (plan-based)
  5. Normalization: Fill defaults, truncate oversized fields
  6. Sanitization: Deep PII scrubbing of all event fields
  7. Enrichment: Attach trace/span IDs, breadcrumbs from context
  8. Deduplication: Suppress duplicate errors within time window
  9. Scope Application: Merge user, tags, extra from global scope
  10. Plugin Processing: Run registered event processors
  11. beforeSend Hook: User callback to modify/drop events
  12. Sampling: Deterministic trace-consistent sampling
  13. Queue: Add to event queue
  14. Persist: Write to disk for crash recovery

Key Design Principles

  • Defensive: SDK never crashes the host application; all errors are caught
  • Resilient: Offline fallback when backend unreachable; circuit breaker prevents cascades
  • Isolated: Plugin failures don't affect other plugins or core functionality
  • Plan-Gated: All features respect plan tier limits enforced by backend
  • Zero-Config: Works out of the box with sensible defaults
Note: The SDK uses AsyncLocalStorage for context propagation, ensuring trace context flows correctly through async operations including promises, callbacks, and timers.
