Pulse SDK for Node.js — Complete Integration Guide

Customer-facing documentation, derived directly from the SDK's source code. For internal architecture, see the Internal Engineering Guide. For the audit methodology behind this content, see the repository audit.

1. Installation#

The package is pure ESM and requires the global fetch API, so Node.js 18 or newer is the practical minimum.

bash 
npm install @vikasbaplawat1/pulse-sdk
pnpm add @vikasbaplawat1/pulse-sdk
yarn add @vikasbaplawat1/pulse-sdk
bun add @vikasbaplawat1/pulse-sdk

The package ships its own TypeScript declarations — no separate @types/ package is needed. It bundles its full OpenTelemetry instrumentation set; @prisma/client and bullmq are optional peer dependencies, installed only if you use those integrations.

2. Quick Start#

Minimal production example:

typescript 
import { createSDK, captureError } from '@vikasbaplawat1/pulse-sdk'

await createSDK({
  apiKey: process.env.PULSE_API_KEY!,
})

try {
  await runApplicationLogic()
} catch (error) {
  captureError(error)
  throw error
}

createSDK is exactly equivalent to calling init. The API key is the only required option and is not read automatically from an environment variable — that convention is application-level, not SDK behavior. Full framework examples (Express, Fastify, plain Node, serverless, workers) are in the complete sdk-docs.md reference file included in this repository's docs/ folder.

3. Configuration#

The only local, application-controlled options live on SDKInitOptions. apiKey is the sole required field. Everything else that affects runtime behavior — features, sampling, entitlements, transport, privacy, killswitches — comes exclusively from the backend's response to the SDK's one initialization request. There is no local override for any of those.

Field Type Default Required
apiKey string — Yes
baseUrl string production SaaS origin No
maxBreadcrumbs number 100 No
shutdownTimeoutMs number 10000 No
debug boolean false No

See the full field table, validation ranges, and common mistakes in docs/sdk-docs.md §3.

4. Auto Features#

Automatic HTTP/HTTPS tracing, Express/Fastify request capture, database/cache/queue instrumentation, automatic error capture, runtime metrics, and console log capture all operate without any manual capture call once enabled remotely. Each is documented in full — purpose, trigger, captured data, disable method, and limitations — in docs/sdk-docs.md §4.

5. Manual API Reference#

All capture helpers are fail-open: internal failures are caught, logged, and swallowed — they never throw into application code.

typescript 
import { captureError } from '@vikasbaplawat1/pulse-sdk'

try {
  await chargeCard()
} catch (error) {
  captureError(error, {
    severity: 'error',
    mechanism: 'checkout.charge',
    fingerprint: 'checkout-charge-v2',
    context: { orderId: 'order_123', retry: false },
  })
}

captureError(error, options?) — never throws, synchronous. captureMessage(message, severity?, context?) — a distinct message event type, gated only by the global disableSDK killswitch. captureRequest(event), captureEvent(event) (returns an EventReceipt), captureLog(level, message, ...args) (up to 10 arguments retained), captureReplay(sessionId, segmentId, events), startProfile/stopProfile (CPU only), and the metrics family (captureMetric, incrementCounter, setGauge, recordHistogram, addUpDownCounter) are all documented in full — signature, parameters, return value, throws, async/sync, examples, common mistakes, and interaction with batching/sampling — in docs/sdk-docs.md §5. Tracing (withSpan, startSpan, getActiveSpan), scope (setUser, withScope), and plugins are covered in the same section.

6. SDK Lifecycle#

typescript 
import { flush, shutdown } from '@vikasbaplawat1/pulse-sdk'

await flush() // drain pipeline and transport; SDK stays active

const result = await shutdown(10_000)
if (!result.completed) {
  console.warn({ timedOut: result.timedOut, remainingEvents: result.remainingEvents })
}

flush() drains without tearing anything down. shutdown(timeoutMs?) never throws and always resolves with a ShutdownResult; it rejects new captures, tears down every subsystem, and resets all global state so a subsequent createSDK() starts clean.

11. Best Practices#

Initialize before requiring instrumented libraries; prefer withSpan() over startSpan(); use withScope() around logical units of work; treat beforeSend as a last-resort filter, not your primary privacy control; call flush() before exiting short-lived processes. Full list in docs/sdk-docs.md §11.

13. Security#

API keys are validated (non-empty, no control characters) before transmission and never logged. Body/header/query/cookie capture is off by default. Client IPs are hashed by default. A hardcoded list of sensitive headers is always redacted in addition to remote configuration. Full detail in docs/sdk-docs.md §13.
