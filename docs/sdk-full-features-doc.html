Feature Summary

Pulse SDK — Complete Feature Guide & Implementation

About This Document

Comprehensive breakdown of every feature in the Pulse SDK — including the workcycle (how it operates from trigger to backend delivery), implementation references with source file locations, and plan tier availability. The SDK is organized into 12 module groups, 34 distinct features, and captures 5 event types.

1. Overview

The Pulse SDK is a zero-config Node.js telemetry SDK that captures errors, performance metrics, distributed traces, and custom events from server-side applications. It is designed to be:

  • Defensive — Never crashes the host application; all errors are caught and logged
  • Resilient — Works offline with reduced capabilities; retries failed sends with backoff
  • Plan-Gated — Enterprise features controlled securely via backend plan tiers
  • Async-Aware — Uses AsyncLocalStorage for per-request context propagation

SDK Communication Contract

EndpointMethodPayloadAuth
/v1/initPOST{ apiKey }apiKey in JSON body only
/v1/eventsPOST{ apiKey, events[] }apiKey in JSON body only
Security Note

API keys are never sent in HTTP headers. They are strictly passed in the JSON body to prevent accidental logging by proxies, load balancers, or CDN middleboxes.

3. End-to-End Event Flow

Every event captured by the SDK flows through this 6-stage lifecycle:

1
Capture Entry Point
User calls a capture function (captureError, captureRequest, captureMessage, captureMetric, captureEvent) or auto-capture via Express middleware / global error handlers triggers this. src/capture/
2
12-Step Event Pipeline
processEvent() orchestrates: assign eventId+timestamp, pre-init buffering, feature gate check, normalize, sanitize PII, enrich with context, error deduplication, apply global scope, plugin processors, user event processors, beforeSend hook, plugin beforeSend, trace-consistent sampling. src/core/event-pipeline.ts
3
Enqueue + Persist
Processed event added to bounded EventQueue (FIFO eviction). Written to NDJSON file for crash recovery. src/transport/queue.ts src/storage/persistent-storage.ts
4
Batching
Batcher timer fires every flushIntervalMs. Guards checked (circuit breaker, rate limiter, memory pressure, concurrency). Queue drained by batchSize. src/transport/batcher.ts
5
HTTP Send with Retry
Batched payload compressed (gzip/brotli), POSTed to ingestUrl with apiKey in body. Failed sends retried with exponential jitter backoff. Global retry budget limits concurrent retries. src/transport/sender.ts src/transport/retry.ts
6
Graceful Shutdown
SIGTERM/SIGINT received. Batcher stopped. Remaining events flushed. Plugins torn down in reverse order. Tracer, session, handlers cleaned up. src/core/lifecycle.ts

6. SDK Initialization & Remote Config

All Tiers
Workcycle
init() called → Zod validation → POST /v1/init → Remote config + plan tier received → Plan features resolved (defaults merged) → Config merged & clamped to plan limits → Subsystems started → SDK ready

Workcycle Phases:

  1. Validation: User options validated against sdkInitOptionsSchema (Zod)
  2. Handshake: POST to /v1/init with API key in body
  3. Plan Resolution: Backend returns plan tier + planFeatures; defaults applied if missing
  4. Config Merge: User options + remote config merged; all features default ON
  5. Plan Clamping: Features above plan tier forced OFF; numeric limits capped; warnings logged
  6. Subsystem Start: Batcher, global error handlers, signal handlers, error deduplicator, metrics registry, session manager (if allowed), OpenTelemetry tracer (if allowed)
  7. Persistent Recovery: Replay events from NDJSON file into queue
  8. Offline Fallback: If /v1/init fails after 5 retries, falls back to errors-only mode (Free plan defaults, enableErrors: true)
src/core/init.ts — Primary implementation (547 lines)
Key Files
  • src/core/init.ts — Main init flow with retry logic (up to 5 attempts, exponential jitter)
  • src/core/client.ts — Singleton SDKClient managing all state (options, config, plugins, breadcrumbs)
  • src/core/plan-gate.ts — Plan defaults, resolution (resolvePlanFeatures), and clamping (clampToPlan)
  • src/types/config.ts — Zod schema (sdkInitOptionsSchema) and all config type definitions
  • src/transport/sender.ts — sendInitRequest() for /v1/init
  • src/core/lifecycle.ts — Graceful shutdown and signal handlers

7. Error Tracking & Crash Reporting

Free Tier+
Workcycle
captureError(err, options?) → Error normalization (toError) → V8 stack parsing → Source map resolution → SHA-256 fingerprinting → Breadcrumb attachment → processEvent() → Pipeline → Queue → Batcher

Implementation Details:

  • Error Normalization: toError() converts any input (Error, string, unknown) to a standard Error object
  • Stack Parsing: parseStack() parses V8 stack traces, handles ESM filenames, eval frames, and classifies frames as in-app (project) vs. library
  • Fingerprinting: generateFingerprint() computes SHA-256 hash of error name + message + in-app stack frames for grouping
  • Source Map Resolution: sourceMapResolver.resolveStackFrames() de-obfuscates production stack traces
  • Severity Override: User can provide custom severity level (debug/info/warning/error/fatal)
  • Custom Fingerprint: User can provide custom fingerprint string via options.fingerprint
  • Custom Context: Arbitrary context object attached via options.context
src/capture/captureError.ts — Entry point

8. Request Monitoring (Performance)

Pro Tier+
Workcycle
monitorMiddleware() registers → Request enters → Context store created (requestId) → HTTP breadcrumb added → Request processing → res.send monkey-patched → finish/close events → captureRequest() → Pipeline → Queue

Implementation Details:

  • Per-Request Context: Each request gets an AsyncLocalStorage context with a unique requestId
  • Response Capture: Monkey-patches res.send() and listens for finish/close events on the response object
  • Body Size Measurement: Measures response body size (Buffer, string, or JSON.stringify)
  • User Identification: Extracts req.user?.id if available (framework-agnostic)
  • Header Sanitization: All headers passed through sanitizeHeaders() before capture
  • Query Parameters: Full query object captured (also sanitized)
  • Slow Request Detection: Every request checked by slowRequestDetector.check()
  • Sampling: Request events are trace-consistent deterministically sampled

10. Metrics Collection

Enterprise Only
Workcycle
captureMetric(name, value, type, options?) → MetricsRegistry aggregation → Timer fires → Flushed as MetricEvent[] → captureEvent() each → Pipeline → Queue

Metric Types:

  • Counter: Monotonically increasing values. incrementCounter(), addUpDownCounter() (can go negative)
  • Gauge: Point-in-time values. setGauge()
  • Histogram: Statistical distributions. recordHistogram() with percentile support

Implementation Details:

  • Client-Side Aggregation: MetricsRegistry aggregates values locally before flush (reduces event volume)
  • Timer-Based Flush: Registry flushes on an internal timer, creating individual MetricEvents
  • Tags/Labels: Metrics support key-value tags for cardinality control
  • Unit Support: Histogram values can have a unit (ms, bytes, count)
  • Direct Capture: If registry not initialized, falls back to direct captureMetric()
src/capture/captureMetric.ts + src/metrics/registry.ts
Key Files
  • src/capture/captureMetric.ts — All metric capture functions
  • src/metrics/registry.ts — MetricsRegistry with histogram percentiles, cardinality protection

  • Resource Detection: Auto-detects OS, hostname, runtime, container ID, cloud provider

20. Event Queue

All Tiers
Workcycle
add(event) → Queue full? → Evict oldest (splice 0,1) → Drop count incremented → Event appended → drain(batchSize) returns first N → requeueFront(events) prepends safely
  • Bounded Capacity: Configured via maxQueueSize (plan-limited)
  • FIFO Eviction: Oldest events evicted when capacity exceeded
  • Drop Notifications: Registered drop handler called on eviction
  • Safe Requeue: requeueFront() prepends in reverse order to avoid call stack overflow

31. Auto-Instrumentation

All Tiers

Express Middleware (monitorMiddleware()):

  • Creates per-request AsyncLocalStorage context with requestId
  • Adds HTTP breadcrumb on request entry
  • Monkey-patches res.send() for response capture
  • Listens for finish/close events
  • Runs slowRequestDetector.check()

HTTP Client Instrumentation (instrumentHttpClient()):

  • Monkey-patches http.request and https.request
  • Creates child span for each outbound request
  • Injects W3C trace context into headers
  • Adds HTTP breadcrumbs on response/error/timeout
  • Self-request guard prevents infinite recursion
  • Idempotent — safe to call multiple times
