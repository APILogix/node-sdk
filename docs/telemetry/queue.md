# Event Queue & Capacity Management

## 1. Overview

The `EventQueue` class in [`src/transport/queue.ts`](file:///c:/Users/vikas/OneDrive/Desktop/APITOOLSDK/sdk-node/src/transport/queue.ts) provides the foundational memory buffer for all telemetry generated by the SDK before transmission.

### Primary Invariant:
> **The aggregate number of events across all priority tiers must never exceed `maxSize` (default: 1,000).**

Under severe network partition or complete control-plane outages, the queue strictly bounds process memory growth and drops lower-priority telemetry deterministically.

---

## 2. Priority Tiers & Ingestion Rules

Events are partitioned into three priority tiers:

| Tier | Telemetry Types | Retention Policy | Eviction Order |
|---|---|---|---|
| **`critical`** | Fatal unhandled errors, process crashes, critical traces | Highest retention; evicts normal/high on overflow | Last to be shed |
| **`high`** | HTTP requests, traces, database spans, crons | Medium retention; evicts normal on overflow | 2nd to be shed |
| **`normal`** | Periodic metrics, standard logs, debug events | Bounded retention; shed first under load | 1st to be shed |

---

## 3. Strict Capacity Ceiling & The Interleaved Traffic Fix

### 3.1 Historical Vulnerability (Pre-Audit)
In earlier versions, `add(event)` evaluated capacity using per-tier checks:
```typescript
if (tier.events.length >= tier.maxSize) {
  // Shed oldest event in tier
}
```
During sustained outages with interleaved streams of critical errors and normal logs, shedding a normal event reduced `totalEvents`, but incoming critical events were admitted as long as their individual tier had space. Over prolonged runs, this allowed the total queue to balloon beyond 12,000 items.

### 3.2 Current Implementation
During the final adversarial audit, a strict global ceiling was implemented:

```typescript
// From src/transport/queue.ts add()
public add(event: TelemetryEvent): boolean {
  const priority = this.classifyPriority(event);

  // STRICT GLOBAL CEILING CHECK
  if (this.size() >= this.maxSize) {
    if (priority !== 'critical') {
      // Normal and high priority items rejected immediately
      this.droppedCount++;
      return false;
    }

    // For critical events, evict oldest normal event first, then high
    const evicted = this.evictLowerPriority();
    if (!evicted) {
      // If queue is 100% full of critical events, drop incoming event
      this.droppedCount++;
      return false;
    }
  }

  // Enqueue to tier
  const tier = this.tiers[priority];
  tier.events.push(event);
  return true;
}
```

---

## 4. Eviction Algorithm

When an incoming critical event arrives and `this.size() >= this.maxSize`:
1. **Pass 1 (Normal Tier):** Check if `tiers.normal.events.length > 0`. If so, `shift()` (discard) the oldest normal event and admit the critical event.
2. **Pass 2 (High Tier):** If normal tier is empty, check if `tiers.high.events.length > 0`. If so, `shift()` the oldest high event and admit the critical event.
3. **Pass 3 (Critical Saturation):** If the entire queue consists purely of critical events, the incoming event is dropped and `droppedCount` is incremented.

## 5. Metrics & Queue Inspection

Queue health can be inspected in real-time via `getSDKHealth()`:

```typescript
import { getSDKHealth } from '@pulse-apm/node';

const health = getSDKHealth();
console.log({
  queueSize: health.queueSize,         // Current events in queue (<= 1000)
  queueDropped: health.queueDropped,   // Cumulative dropped count
  queueDeadLetter: health.queueDeadLetter,
});
```
