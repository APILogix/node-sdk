## Data Flow

1. **Initialization**: The application boots with `--import @pulse-apm/node/register` or calls `Pulse.init({ apiKey: "..." })`.
2. **Inbound Request**: An HTTP request reaches Express/Fastify. The SDK starts an HTTP server span and stores it in `AsyncLocalStorage`.
3. **Execution & Interception**:
   - When application code executes `User.findOne()` or `prisma.session.create()`, the patched prototype interceptor extracts the active context.
   - A child database span is created (`parentSpanId === handler.spanId`).
   - The original database operation executes.
   - On completion (or error), the span is closed with execution metrics and status.
4. **Processing**: Spans are passed through `SecurityScrubber` to remove secrets and SQL query parameter values.
5. **Buffering**: Processed spans enter `BatchManager`. If memory queues saturate, events overflow into `PersistentStorage` on disk.
6. **Delivery**: The transport worker compresses batches using Gzip and sends an HTTP POST request to the Pulse ingestion endpoint.

## Technical Debt & Conventions

### Observed Conventions
- **Language**: TypeScript (`ES2022`, module resolution: `NodeNext`).
- **Module System**: Dual support for native ESM (`"type": "module"`) and CommonJS.
- **Fail-Open Policy**: Every interceptor wraps execution in defensive `try/catch` blocks; APM errors must never crash host application logic.
- **Deduplication**: Logical ORM spans suppress underlying driver spans using context symbols.

### Technical Debt / Areas for Improvement
- [ ] `SlowRequestDetector`: Marked as deprecated since v3.0 (now handled server-side via OTel histograms). Candidate for removal in next major release.
- [ ] ESM Hook Registration: Currently relies on Node's `--import` CLI flag; runtime ESM monkey-patching remains limited by Node's native module loader freeze.
- [ ] Test Suite Isolation: Integration tests spawn live SQLite/local mock servers; Windows file lock semantics require guarded cleanup in `persistent-storage` tests.
