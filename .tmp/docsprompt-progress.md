## SHUTDOWN/LIFECYCLE FACTS (src/core/lifecycle.ts)
- shutdown(timeoutMs?) is single-flight (shares in-flight promise for concurrent callers). Sets shuttingDown=true immediately (capture paths check isSDKShuttingDown()).
- Timeout resolution: explicit param > client.options.shutdownTimeoutMs > DEFAULT_SHUTDOWN_TIMEOUT_MS=10_000.
- Races `completion` (the real cleanup) against a timeoutPromise; if timeout wins, timedOut=true but `completion` KEEPS RUNNING in background (shutdownCompletionPromise) — init()'s waitForShutdownCompletion() blocks a subsequent init until this finishes, guaranteeing no two cleanups/inits race.
- runOrchestratedShutdown() ordered steps (each wrapped w/ per-step timeout, non-fatal on error, recorded in stepErrors[]):
 1. beforeShutdown hooks (registered via onBeforeShutdown()) — HOOK_TIMEOUT_MS=5000 each, run in registration order
 2. eventQueue.setShuttingDown(true) — stop accepting new events at queue boundary
 3. metricsRegistry.flush(true) pre-teardown (marks internal so shutdown-time emission still gets admitted) — SUBSYSTEM_STEP_TIMEOUT_MS=5000
 4. featureController.teardownAll() — tears down each registered feature subsystem via its teardown callback
 5. flushTracer() — force-flush OTel spans into pipeline before transport shuts down
 6. drainPendingEventProcessing() — drains in-flight event-pipeline setImmediate work (see event-pipeline.ts pipelineDraining flag)
 7. metrics flush again (final snapshot+export) then otelMetrics.shutdown() then metricsRegistry.stop()
 8. flush() (module-level: drains pipeline again(no-op if already drained) + TransportRouter.flushAll() + persistentStorage.flush())
 9. teardownPlugins() — plugin.teardown() hooks, after their telemetry already flushed
 10. shutdownTracer() — releases OTel context manager + processors
 11. CronSubsystem.reset(), ProfilingSubsystem.reset(), LoggingSubsystem.reset(), resetSessionManager() — LIFO vs their init order
 12. resetGlobalErrorHandlers() — removes uncaughtException/unhandledRejection listeners + unwraps console.error + restores Error.stackTraceLimit
 13. errorDeduplicator.stop()+reset() — stops its cleanup timer
 14. persistent-storage.drain — TWO sources: (a) TransportRouter.shutdown() returns "residual" undelivered events (batches that couldn't be sent — network down/retry exhausted) -> persistentStorage.persistBatch(residual); (b) legacy eventQueue.drainAll() -> persistentStorage.persist() each. Order matters: BatchManager residuals first (bigger backlog under outage), then legacy queue. Then persistentStorage.flush().
 15. persistentStorage.shutdown() — drains write chain, marks uninitialized, releases file handle
- runUnconditionalCleanup() — ALWAYS runs even if orchestrated shutdown threw/timed out (hard reset for clean reinit): TransportRouter.shutdown() again (idempotent-safe) then null singletons: eventQueue.clear()+shutdown-flag reset, resetEventPipeline(), client.clear(), ConfigManager.reset(), FeatureController.reset(), KillswitchEngine.reset(), EntitlementGate.reset(), SamplingEngine.reset(), LimitsEngine.reset(), SecurityScrubber.reset(), resetGlobalErrorHandlers() again, LoggingSubsystem.reset(), CronSubsystem.reset(), resetSignalHandlers() (removes SIGTERM/SIGINT process listeners — this is why re-init is safe, no handler stacking), resetAutoInstrumentations(), tenantGovernor.reset(), cardinalityGovernor.shutdown()+reset(), adaptivePressure.stop(), SerializationPool.reset() (terminates worker threads — awaited so they can't hold process open).
- shutdown() NEVER throws; returns ShutdownResult {completed,timedOut,durationMs,remainingEvents,deadLetterCount,stepErrors[]}.
- flush(timeoutMs? none, no param) = drainPendingEventProcessing() + TransportRouter.flushAll() + persistentStorage.flush(). Does NOT tear down runtime. Can be called anytime.
- crashFlush(timeoutMs=2000) = races (drainPendingEventProcessing (best-effort swallow) + router.flushAll()) against hard timeout; swallows ALL errors; NO subsystem teardown, NO plugin teardown, NO persistence flush call explicitly (only transport flushAll). Documented as crash-path-only, lightweight.
- registerSignalHandlers(): idempotent (flag-guarded), uses process.on (not once) so removal is explicit via resetSignalHandlers(), avoiding handler stacking across reinit. Handles SIGTERM+SIGINT only — SIGKILL cannot be handled (matches README).
- onBeforeShutdown(hook) — public-ish (exported from lifecycle.ts but NOT re-exported from index.ts -> confirm: index.ts does NOT export onBeforeShutdown or isSDKShuttingDown -> these are internal-only, not in public surface, not in internals.ts either -> truly module-private-ish (exported from module but not part of any documented surface). Note for audit: "exported but not part of public or internals surface" = candidate for audit report finding.
